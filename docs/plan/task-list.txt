v1 — ordered task list
======================

1. Project skeleton — Web app scaffold, env handling, basic layout/navigation (sheets list, sheet detail).

2. Database — Migrations for users, sheets, sheet_repos, log_entry_runs, log_entries (per docs/plan/db.txt); local/dev DB wired up.

3. Auth — Sign-in (email/password or GitHub OAuth—pick one); user_id on all owned records.

4. GitHub access — Store PAT (or OAuth token) securely; server-side helper to call GitHub API with pagination and basic error handling.

5. Sheets: CRUD — Create/rename/list/delete sheets; empty state.

6. Sheet repos — UI to add/remove repos on a sheet (owner + name); persist sheet_repos; validate input.

7. “Create log entry” flow — Pick date range → for each sheet_repo, fetch commits on main in range (no author filter) → build one draft row per repo: from/to, project = repo name, description = joined commit messages; time blank/0.

8. Review & save — Editable form per row (or batch table); save creates log_entry_run + log_entries in DB.

9. List log entries — Show saved entries for a sheet (filter by run optional); edit/delete entry if you want v1 polish.

10. Export — “Generate Excel” from DB for a sheet (columns: from, to, task, time, project, notes); download .xlsx.

11. Hardening — Rate-limit awareness, loading/error states, confirm destructive actions, timezone display consistent with stored values.

Optional before ship
--------------------
Minimal tests on GitHub fetch + DB writes; README with env vars and how to run.
